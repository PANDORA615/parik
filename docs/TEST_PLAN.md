[Результаты реально выполненных команд](VERIFICATION.md), [полный список ручных проверок](MANUAL_TESTS.md), [карта требований](REQUIREMENTS.md).

## Автоматические тесты

| Набор | Проверки |
|---|---|
| `RulesTest` | Валидация, деньги в minor units и разные валюты, строгие даты, DST, телефон без угадывания страны, все блокирующие статусы, соседние/вложенные/полуночные интервалы, редактирование себя, свободные слоты и рабочие часы |
| `BackupTest` | Round trip сущностей и настроек, обязательная версия, неправильные ссылки/UUID/дубли, конфликтующие визиты, пустой/повреждённый/слишком большой поток |
| `RepositoryTest` | Конкурирующие транзакции, CRUD, перенос/отмена, FK и архивы, отказ неверного restore без изменений, восстановление связей/настроек, журнал после прерывания, day Flow через полночь, переименование и снимки, повторное открытие дисковой БД и индексы |
| `SalonUiTest` | Ручной клиент, поиск по телефону, выбор услуги и запись, сохранение при recreation, отмена, перенос, конфликт, стрелки/Сегодня, пустые состояния, создание услуги в каталоге без подмены услуги существующей записи |
| `ReminderTest` | Отменённый, перенесённый, удалённый визит и отключённые напоминания не вызывают старое уведомление |
| `ContactClientFlowTest` | «Добавить клиента» → «Из контактов» запускает picker; отмена оставляет ручной ввод; Activity recreation не повторяет запуск; созданный клиент возвращается в запись с сохранением даты, времени, услуги, длительности и цены. Системный ответ отмены подменён Espresso Intents, реальный провайдер контактов требует ручной проверки |
| `PerformanceTest` | Синтетические 5000 клиентов и 20000 визитов: корректность и время запроса дня/загрузки и фильтрации клиентов; не заменяет измерение на физическом устройстве |

```bash
./gradlew testDebugUnitTest lintDebug assembleDebug assembleRelease bundleRelease
./gradlew connectedDebugAndroidTest
```

GitHub Actions выполняет сборку и матрицу эмуляторов API 26/29/30/33/34/36; наличие workflow не означает, что все запуски уже прошли. Отчёты и APK/AAB публикуются как артефакты успешных соответствующих задач. В первой схеме Room v1 нет перехода миграции; следующая схема требует теста миграции из экспортированной v1, разрушительный fallback не используется.
