# Решения MVP

Один модуль `app`, пакеты `domain`, `data`, `platform`, `ui`. Простой DI через `SalonApplication`: у приложения один экземпляр Room, репозитория и DataStore. Hilt здесь добавил бы настройку без дополнительной пользы. ViewModel получает зависимости из Application; Compose получает состояние и отправляет события, не выполняет SQL. Navigation Compose хранит стек, `SavedStateHandle` — выбранный день, `rememberSaveable` — черновики форм. Корутины Room/DataStore и файловые операции выполняются вне главного потока.

## Данные

Room v1, экспортированная схема в `app/schemas`. Разрушительные fallback-миграции отключены. Это первая версия пустого репозитория: переходов между версиями ещё нет; следующее изменение схемы требует увеличения версии, `Migration` и проверки исходной схемы. UUID, FK RESTRICT, индексы по времени, клиенту/времени, статусу/времени, услуге и нормализованному телефону. День — полуоткрытый интервал между двумя локальными началами суток, что учитывает 23/25-часовые дни. Пересекающие полночь визиты показываются в обоих днях.

Начало визита — epoch milliseconds (Instant); длительность — реальные минуты. Зона устройства применяется при отображении. При смене зоны сохраняется абсолютный момент, меняется отображаемое местное время. При вводе несуществующего времени DST — ошибка; для повторяющегося часа выбирается первое смещение. Длительность ограничена 1–10080 минутами для защиты от ошибочного ввода. Цены — Long в минимальных единицах валюты, ввод через BigDecimal без округления. Количество знаков определяется ISO-валютой. RUB — редактируемое начальное значение; итоги разных валют не складываются.

Исторические названия услуги/клиента сохраняются в снимках. Расписание и карточка показывают актуальное имя связанного клиента; название услуги визита остаётся историческим. Переименование услуги не меняет её снимки. Клиенты/услуги архивируются, FK и история сохраняются. Архивные сущности разрешено оставлять только в существующих связанных визитах.

## Бронирование

`SalonRepository.saveAppointment`: валидация → Room-транзакция → проверка FK/архива → проверка всех пересекающихся PLANNED интервалов без ограничения датой начала → сохранение. Проверка и запись неразделимы. Mutex сериализует операции репозитория; Room сериализует транзакции. Редактируемый UUID исключается. Интервалы `[start, end)`, поэтому соседние записи разрешены.

Только PLANNED блокирует время — как в будущем, так и в прошлом. COMPLETED, CANCELLED, NO_SHOW не блокируют время, в том числе при создании записи задним числом. COMPLETED и NO_SHOW разрешены после момента начала визита, включая ещё идущий визит. Можно исправить любой статус в редакторе; возврат в PLANNED повторно проверяет конфликты и часы. Вне графика требуется отдельное явное подтверждение. Конфликт обойти нельзя. Отдельных блокировок перерывов в этой версии нет.

Свободные слоты формируются внутри рабочего дня с выбранным шагом 15/30/60 минут и учитывают полную длительность и записи соседних дат. Доступность повторно проверяется при сохранении. Создание клиента/услуги из формы не закрывает её и не сбрасывает поля.

## Настройки и восстановление

Настройки хранятся в Preferences DataStore. Формат резервной копии — JSON v1; не более 20 МБ при чтении; неизвестные поля/статусы, неверные UUID, дубли ID, некорректные поля, ссылки и конфликты PLANNED отклоняются до изменения БД. Копия содержит все архивы, снимки и настройки. Экспорт через SAF, без URI исходных контактов.

Восстановление — полная замена после просмотра количества сущностей и подтверждения. Удаление старых строк, вставка новых и запись снимка настроек в `pending_settings` выполняются одной Room-транзакцией. Журнал имеет приоритет над DataStore до завершения его записи. Если процесс прервётся между Room и DataStore, новая база всё равно читается с восстановленными настройками. При следующем старте журнал переносится в DataStore. Некорректный файл не меняет ни базу, ни настройки. Случайный обрыв записи экспортируемого документа может оставить неполный внешний файл; импорт такой файл отклонит, локальная БД не меняется.

## Платформа и приватность

Контакты: PickContact → только выбранный URI и его `entities` → предпросмотр → выбор одного из доступных номеров → редактирование → сохранение. Нет READ_CONTACTS. Некоторые приложения контактов/OEM не выдают доступ к подкаталогу; тогда остаётся имя и ручной ввод номера. Отмена picker сохраняет форму, SecurityException обрабатывается. Номер не связывает клиента с внешней телефонной книгой. Нормализация убирает оформление и сохраняет международный `+`; код страны не угадывается, `8…` и `+7…` не объединяются. Дубликаты активных клиентов требуют выбора, автоматического объединения нет. ACTION_DIAL без CALL_PHONE.

WorkManager создаёт уникальную отложенную работу для будущего PLANNED визита, пересогласует работы при изменениях базы/настроек и старте приложения. Worker повторно проверяет ID, редакцию, статус и настройку перед нейтральным уведомлением. Отмена/удаление/перенос отменяют старую работу. Уведомления приблизительные, не AlarmManager; после старта визита допускается задержка до 15 минут, более старое напоминание пропускается. На Android 13+ разрешение спрашивается при включении, отказ не блокирует ежедневник. Разрешение не переносится из JSON: после импорта может потребоваться повторное включение в настройках ОС. Не отображаются имена, телефоны или заметки на экране блокировки.

Автоматическое облачное резервирование и перенос данных Android отключены; база во внутреннем каталоге. Приложение не запрашивает INTERNET, READ_CONTACTS и CALL_PHONE, не включает аналитику и рекламу. Ручной JSON не шифруется, об этом есть предупреждение до экспорта. Ключ подписи и персональные данные не включаются в репозиторий. Пользователь отвечает за защищённое хранение копий и законные основания обработки данных клиентов.
